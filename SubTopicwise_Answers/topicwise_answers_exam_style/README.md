# Topic-wise Exam-style Answers

One file per subtopic that has at least one past-paper question. **84 files.**

Nothing in this folder is written by hand. Every block is generated from
`../answers_exam_style/`, which is the only place an answer is authored, by
`scripts/gen_topicwise.py`. The number in a block here is the same characters
as the number it was copied from.

Three gates check that, and each was verified by breaking the folder on purpose
and watching the right one fail:

| Gate | What it holds |
| :-- | :-- |
| **V8** | every box and every long numeral traces to a year-wise section |
| **V14** | no box is retyped, every cited unit is real, no pointer is dead |
| **V3** | every unit appears in exactly one block, in exactly one file |

## Why one file per subtopic

`PreviousYearQuestions/topic_subtopic_list.md` defines 105 subtopics across 17
clusters. 84 of them have been examined. The other 21 have no exam presence at
all and get **no file, no stub, no placeholder**.

## The merge rule

Repeated questions are not answered twice. When the same method meets the same
structure, the answers become one block that lists every appearance:

| Tier | Meaning | Action |
| :-- | :-- | :-- |
| L1 | Asked once. No repeat to merge. | Its own block |
| **L2** | **Same method, same structure, numbers changed** | **One block, written from the earliest appearance, listing every appearance.** This is the rule. |
| L3 | Same topic, different method or structure | Never merged. Each is its own block, shown in sequence. |

A unit is written **in full in exactly one file**: the one it is filed under. A
subtopic that reaches it only through a cross reference gets a pointer line, not
a second copy. Writing it twice is the defect V3 exists to catch.

`scripts/merge_map.csv` holds every decision, and it is itself generated by
`scripts/build_merge_map.py`. Both this folder and
`../topicwise_answers_explanation/` read that one file, and gate **V4** compares
their block headings and provenance lines byte for byte, so the two cannot drift
apart. That drift is what broke the ECE 2207 build, 130 times out of 200.

## Block shape

```
### [2024 Q.3(b)]: Census Population, Estimate 1995

**Appeared in:** 2017 Q.5(c), 2020 Q.3(b), 2024 Q.3(b)

**Question.** The population of a town in decennial census were as following table in
thousand units. Estimate the population for the year 1995.

**Solution.** ...
$$\boxed{P(1995) = 20.1888 \text{ thousand}}$$
```

## Naming

`NM-4.6_Lagranges_Interpolation.md`

Taxonomy ID first, then the title. The ID stays readable even if the title is
edited later. No `T-NN` scheme: that numbering collided in ECE 2207.

The names are generated by `scripts/build_filelist.py` from the headings in
`PreviousYearQuestions/topic_wise_sorted_questions.md`, so an edit to a title
there propagates here and the two cannot disagree. An earlier hand-written list
had twelve slugs truncated mid-phrase, two of them identical to each other.

## Cross references

`*NM-x.y*` pointer lines name the subtopic a question is written in. A pointer
to a subtopic with no file would be a dead link, so it points at
`topic_subtopic_list.md` instead. Gates V7 and V14 check every one, and a
pointer-only file states in prose that it owns no block, so an empty file is
visibly deliberate rather than looking like an omission.

**Four subtopics hold no block of their own.** NM-3.8, NM-5.6, NM-5.7 and
NM-10.4 are never a primary filing in `answer_manifest.csv`; every question that
reaches them is written in the subtopic it is filed under, and their files are
lists of pointers. That is correct, not thin.

No em dashes. Plain words.
